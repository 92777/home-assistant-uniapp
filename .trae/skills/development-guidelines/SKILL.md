# Home Assistant UniApp 开发规范

## 开发环境配置

### 本地调试
- **使用 Vite 服务器**进行本地调试
- 运行命令: `npm run dev:h5`
- 调试地址: 通常为 `http://localhost:5173`

## 代码修改规范

### 代码修改
- **禁止在未经同意的情况下大面积修改代码**
- 如需进行较大改动,请先与团队沟通确认
- 保持代码修改的最小化和针对性

### 日志管理
- **非必要不要创建过多的日志进行调试**
- 生产环境应移除所有调试日志
- 使用 `console.log()` 时应考虑日志级别的合理性

### 版本管理
- **不要创建过多的易混淆的备份版本**
- 使用 Git 进行版本控制,避免手动创建备份文件
- 保持仓库整洁,避免提交不必要的文件

## 前端开发规范

### 代码复用
- **开发过程中尽可能的进行代码复用**
- 抽取公共组件和工具函数
- 建立合理的组件层次结构
- **不要将所有代码都写入一个index.html**，尽可能进行封装和复用

### 数据与样式分离
- **隔离数据与样式**,通过 Vue 的数据绑定概念实现
- 不要在处理完数据之后再去操作样式
- 利用 Vue 的响应式系统,让数据驱动 UI 变化

### 数据缓存策略
由于数据量不大,需要**尽可能的缓存**以下信息:

1. **账号信息**
2. **房间信息**
3. **设备信息**
4. **实体信息**
5. **实体状态**

### 数据更新策略
- 数据有变化时,**只修改缓存**
- 样式根据绑定的结果**动态展示**
- 利用 Vue 的计算属性和监听器处理数据变化

## 性能优化

### 渲染性能
- 使用 `v-if` 和 `v-show` 合理控制元素显示
- 避免不必要的 DOM 操作
- 合理使用 `key` 属性优化列表渲染

### 网络请求
- 减少不必要的网络请求
- 利用缓存减少重复请求
- 合理使用 WebSocket 进行实时数据更新

## 代码质量

### 代码风格
- 遵循项目的代码风格规范
- 保持代码缩进和格式的一致性
- 为关键代码添加注释说明

### 错误处理
- 完善的错误处理机制
- 合理的异常捕获和提示
- 避免静默失败

## 安全规范

### 认证信息
- 安全存储访问令牌
- 避免在代码中硬编码敏感信息
- 使用环境变量或安全的存储方式

### 网络安全
- 使用 HTTPS 协议
- 验证 API 响应数据
- 防止 XSS 攻击

## 开发工作流

1. **需求分析**: 理解功能需求和技术要求
2. **API 文档分析**: 基于 API 文档进行开发，如果文档不清晰，需要自行调试文档中的 API，然后根据结果继续开发
3. **设计规划**: 设计组件结构和数据流程
4. **代码实现**: 按照规范实现功能
5. **测试验证**: 确保功能正常运行
6. **代码审查**: 检查代码质量和规范遵守情况
7. **部署发布**: 按照流程部署到生产环境

## API 使用规范

### API 文档遵循
- **所有的开发均基于 API 文档**
- 如果文档不清晰，需要自行调试文档中的 API，然后根据结果继续开发
- **禁止幻想一些不存在的字段或者接口**
- 如果 API 文档中没提到，但是调试出来的结果可以写入 API 文档中

### 数据层级管理
- **数据层级需要树立清晰**，不要搞得各是各
- 建立合理的数据结构和层级关系
- 保持数据的一致性和可追溯性

## 技术栈使用

### 核心技术
- **Vue 3**: 前端框架
- **UniApp**: 跨平台开发
- **Vite**: 构建工具

### API 集成
- **REST API**: 用于获取配置、实体状态等
- **WebSocket API**: 用于实时事件订阅

### 工具库
- **Hutool**: 用于 JSON 序列化、日期格式化等
- **Vue Composition API**: 用于状态管理和逻辑复用

## 命名规范

### 组件命名
- 使用 PascalCase 命名组件
- 组件名称应具有描述性
- 避免使用过于通用的名称

### 变量命名
- 使用 camelCase 命名变量
- 常量使用全大写字母加下划线
- 函数名应清晰表达其功能

### 文件命名
- 组件文件使用 PascalCase
- 工具文件使用 camelCase
- 保持文件命名的一致性

## 注释规范

### 组件注释
- 组件应包含功能描述
- 说明组件的 props 和事件
- 标注关键逻辑和注意事项

### 代码注释
- 复杂逻辑应有注释说明
- 关键算法应解释其原理
- 特殊处理应标注原因

## 测试规范

### 单元测试
- 关键功能应有单元测试
- 测试覆盖核心逻辑
- 确保测试用例的可维护性

### 集成测试
- 测试组件间的交互
- 验证 API 调用的正确性
- 确保整体功能的完整性

## 文档规范

### 代码文档
- 为公共 API 添加 JSDoc 注释
- 说明函数的参数、返回值和使用方法
- 保持文档与代码的同步更新

### 项目文档
- 维护项目结构说明
- 记录关键功能的实现方案
- 提供开发和部署指南

## 总结

遵循以上开发规范,可以提高代码质量,减少开发过程中的问题,确保项目的可维护性和可扩展性。团队成员应共同遵守这些规范,形成良好的开发习惯。
